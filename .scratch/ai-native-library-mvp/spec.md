# AI 原生图书管理系统 —— MVP 规格

Status: ready-for-agent

## Problem Statement

学校与中小型公共图书馆缺乏负担得起的图书管理系统：传统 ILS 面向专业馆员设计（MARC 编目门槛高、流程繁重），而学校与小型馆通常没有专职编目员和 IT 支持。现有系统的检索仍是字段匹配，读者难以用自然语言找到书。馆藏运营（借还、逾期、班级套书）依赖纸质台账或过重的大型系统，AI 能力基本缺位。

## Solution

一个 AI 原生的 Web 图书管理系统，以学校图书馆为优先场景（兼容公共馆）。馆员通过扫码与自动编目快速建库，完成日常流通运营（借还、续借、逾期跟踪、班级套书借阅）；读者通过免登录的**公共检索**用**自然语言检索**找到书并获得**架位号**指引。系统核心闭环（目录、流通、读者管理）在**无 AI 时完整可用**（AI 降级为硬约束）。借阅政策可配置，AI 贯穿读者端与馆员端工作流但受显式边界约束（降级/引用/确认/审计/成本）。

## User Stories

### 读者（Reader）

1. 作为读者，我想用自然语言描述阅读需求进行检索（如"找一本讲二战的入门书"），以便不需要知道精确书名也能找到书。
2. 作为读者，我想看到检索结果按相关度排序，以便快速找到最匹配的书。
3. 作为读者，我想查看结果中每本书的架位号，以便直接去书架取书。
4. 作为读者，我想免登录使用检索，以便任何访客都能使用。
5. 作为读者，我想查看书籍详细信息（作者、出版信息、简介、主题），以便判断是否适合我。
6. 作为读者，我想知道书当前是否可借（在馆/借出/逾期未还），以便决定是否去取。
7. 作为读者，我想让馆员代查我的借阅记录，以便了解借了什么、何时到期。

### 馆员（Librarian）

8. 作为馆员，我想扫描 ISBN 自动生成书目元数据，以便不手工编目即可快速建库。
9. 作为馆员，我想在 AI 建议的元数据入库前逐条审核确认，以便保证目录质量。
10. 作为馆员，我想看到元数据字段的来源标注（外部书目库 / AI 生成），以便做出信任判断。
11. 作为馆员，我想批量导入馆藏清单（CSV/Excel），以便有电子目录时快速建库。
12. 作为馆员，我想创建题名记录并登记副本（条码、架位号），以便管理一题多副本。
13. 作为馆员，我想扫描读者身份与副本条码完成借出，以便快速办理。
14. 作为馆员，我想在借出时得到借阅政策校验（数量上限、期限），以便自动遵守政策。
15. 作为馆员，我想扫描条码完成归还，以便快速办理。
16. 作为馆员，我想为读者办理一次续借，以便延长借期。
17. 作为馆员，我想查看逾期借阅列表，以便提醒读者归还。
18. 作为馆员，我想为班级借出一批套书（关联班级、按学期计期），以便支持整班阅读。
19. 作为馆员，我想查看某读者的当前借阅，以便回答读者查询。
20. 作为馆员，我想登记读者档案（学生/教师，关联班级/年级），以便建立读者台账。
21. 作为馆员，我想修正目录元数据，以便纠正错误。
22. 作为馆员，我想在 AI 不可用时仍完成借还、检索与编目（降级路径），以便运营不中断。
23. 作为馆员，我想看到检索命中与编目字段的引用依据，以便解释结果来源。
24. 作为馆员，我想在办理借还时看到读者的逾期状态警告，以便管理借阅风险。

### 系统管理员（System Administrator）

25. 作为系统管理员，我想创建与停用馆员账号，以便控制系统访问。
26. 作为系统管理员，我想配置借阅政策（期限、数量上限、续借次数），以便适配不同学校。
27. 作为系统管理员，我想配置 AI 供应商与调用成本限额，以便控制支出。
28. 作为系统管理员，我想查看 AI 操作审计日志，以便合规回溯。
29. 作为系统管理员，我想备份与恢复数据，以便容灾。
30. 作为系统管理员，我想将系统部署到校内服务器或云端，以便按学校环境选择。

## Implementation Decisions

### 应用与部署

- **TypeScript 全栈 Web 应用**，单租户、每馆独立实例；同一套代码支持**自托管（校内服务器）与云端托管**两种部署形态。
- 角色权限矩阵：**读者**无系统权限（仅公共检索）；**馆员**持有全部业务操作（流通、读者管理、编目与审核、逾期）；**系统管理员**仅系统级事项（账号、配置、备份、审计）。

### 领域模型

- **题名/副本分层**：题名承载书目元数据，副本为实体实例（条码标识、架位号）；一题名可有多副本。数据模型为**数字资源**预留扩展位（v1 不实现）。
- **借阅**两种类型：**个人借阅**与**班级套书借阅**。
- **借阅政策**可配置：期限、数量上限、续借次数；学校默认值 = 学生 2 周/同时 5 本、教师 4 周、班级套书 1 学期、可续借 1 次、无罚款、逾期跟踪。
- **读者** = 学生与教师，一人一账户，关联班级/年级；**无读者登录**（未成年人数据隐私，ADR-0002），借阅记录由馆员代查。

### 目录与编目

- 目录元数据采用**简化字段 + AI 增强**，不引入 MARC（ADR-0001）：题名、作者、ISBN、分类、主题、出版信息。
- **自动编目**：优先调用**外部书目数据库**（Open Library / 豆瓣 / 国家图书馆），缺失字段由 LLM 补全。
- **编目审核门**：AI 建议的元数据必须经馆员确认后才进入目录；**AI 永不静默写库**。
- **来源标注**：每个元数据字段标注来源（外部书目库 / AI 生成 / 馆员手录），便于信任判断与审计。

### 检索

- **公共检索**免登录开放；**自然语言检索**为默认检索方式，**关键词检索**为降级路径（AI 不可用或超时时自动切换）。
- 检索结果含：相关度排序、书籍详情、当前可借状态、架位号指引。

### 流通

- 借还、续借、班级套书借出均为**馆员操作**。
- 逾期：无罚款，但跟踪并呈现逾期列表与读者逾期状态警告（馆员端）。
- 借出时执行政策校验（上限拒绝、期限计算）。

### AI 接入

- **供应商抽象层 + 默认国内模型**（DeepSeek、通义千问、智谱等，可切换），契合未成年人数据合规（ADR-0002）。

#### AI 边界（显式约束）

- **降级**：AI 不可用/超时 → 检索退化为关键词检索、编目退化为手工录入；流通与读者管理**零依赖 AI**。无 AI 时系统完整可用是硬性约束。
- **引用**：自然语言检索结果引用命中的题名与匹配依据；编目字段标注来源（外部书目库 vs AI 生成），AI 生成字段明确标记，禁止与权威来源混淆。
- **确认**：一切 AI 生成的入库内容须经馆员确认（编目审核门）；AI 永不静默写库。
- **审计**：所有 AI 调用与操作留痕（时间、操作者、输入、输出、确认/拒绝结果），支持未成年人数据隐私合规回溯（ADR-0002）。
- **成本**：AI 调用限额（单次检索超时与单查询上限）、编目批量处理与结果缓存、成本跟踪与预算护栏；离线评测不计入生产成本。

### 初始建库

- **扫码自动编目**（扫描 ISBN 逐本入库）为主路径，**CSV/Excel 批量导入 + 自动编目补全**为辅助路径；手工录入兜底。

## Testing Decisions

- **好测试的定义**：只验证外部行为，不测实现细节；领域行为通过应用服务公共接口验证，集成行为通过 HTTP/API 验证，关键旅程通过浏览器验证，AI 质量通过离线评测验证。测试与实现隔离，重构不破测试。
- **Seam 1 —— 应用服务公共接口（主 seam）**：领域行为 —— 流通状态转换（借出/归还/续借/逾期）、政策边界（超上限拒绝、期限计算）、编目审核门（未确认不入目录）、读者建档与班级关联。无 I/O、无 UI，承载绝大多数测试。
- **Seam 2 —— HTTP/API 公共接口**：集成行为 —— 馆员操作 API 契约（借还、审核）、公共检索 API（免登录）、自动编目外部书目库集成（mock 外部依赖）、真实持久化、权限校验（馆员 vs 管理员）。
- **Seam 3 —— 浏览器**：最关键用户旅程（约 3–5 条）—— 馆员扫码借还闭环（含逾期视图）、公共自然语言检索 → 结果 → 架位指引、编目审核流（AI 建议 → 确认入库）。
- **Seam 4 —— AI Assistant 公共接口（离线评测）**：固定评测集 + 录制/固定的模型输出，CI 离线可跑；golden 自然语言查询 → 期望题名集合、golden ISBN → 期望元数据。指标为**检索命中率/排序质量、编目字段准确率**（非逐字断言），这是唯一验证 AI 输出质量的 seam。
- **被测模块**（概念层）：流通服务、目录/编目服务、读者服务、检索接口、AI 编目与检索接口。
- **Prior art**：全新代码库，无既有测试先例；遵循仓库 skills 的 TDD 工作流（测试先行）。

## Out of Scope

- 读者自助账户与读者端登录（v2，需先评估隐私影响，见 ADR-0002）
- 罚款、预约/预借、馆际互借（公共馆阶段）
- 数字资源（电子书/有声书）流通与访问授权
- 采编（acquisitions）与统计报表
- 多租户 SaaS 与多分馆
- RFID 硬件与自助借还设备
- 对话式多轮助手与个性化推荐
